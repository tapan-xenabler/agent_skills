## Execution Steps (Run in Strict Order)

### Step 0 — Pre-flight Check: Initialize Fastlane if Missing

Before building, verify if Fastlane is already set up in the project:
1. Check if `fastlane/Fastfile` exists.
2. **If `fastlane/Fastfile` already exists:** Skip this step and do NOT modify it.
3. **If `fastlane/Fastfile` is missing (e.g. New Project):**
   - Notify the user: `"⚡ Fastlane setup missing. Initializing Fastlane configuration for Android..."`
   - Create or update `Gemfile` in the project root:
     ```ruby
     source "https://rubygems.org"
     gem "fastlane"
     gem "fastlane-plugin-google_drive_uploader"
     gem "fastlane-plugin-firebase_app_distribution"
     ```
   - Create `fastlane/Pluginfile`:
     ```ruby
     # Autogenerated by fastlane
     gem 'fastlane-plugin-google_drive_uploader'
     gem 'fastlane-plugin-firebase_app_distribution'
     ```
   - Create `fastlane/Fastfile` with the standardized template:
     ```ruby
     default_platform(:android)

     platform :android do
       desc "Build APK and upload to Google Drive"
       lane :build_apk do |options|
         flavor = options[:flavor]
         build_type = options[:build_type] || "Release"
         should_upload_to_gdrive = options[:upload_to_gdrive].to_s == 'true'

         task_variant = (flavor && !flavor.strip.empty?) ? "#{flavor}#{build_type.capitalize}" : build_type.capitalize
         gradle_task = "assemble#{task_variant}"

         UI.message("Executing Gradle task: #{gradle_task}")
         gradle(task: gradle_task)

         apk_path = lane_context[SharedValues::GRADLE_APK_OUTPUT_PATH]

         if apk_path && File.exist?(apk_path)
           UI.success("APK successfully built: #{apk_path}")

           if should_upload_to_gdrive
             drive_folder_id = options[:drive_folder_id] || ENV["GDRIVE_FOLDER_ID"]
             if drive_folder_id
               google_drive_uploader(
                 client_secrets_path: "./fastlane/client_secrets.json",
                 token_store_path: "./fastlane/gdrive_token.yaml",
                 file_path: apk_path,
                 folder_id: drive_folder_id,
                 make_public: true
               )
             else
               UI.important("Google Drive Folder ID not provided. Skipping upload.")
             end
           end
         end
       end
     end
     ```
   - Ensure `fastlane/client_secrets.json` and `fastlane/*.yaml` are added to `.gitignore`.
   - Run `bundle install` in the background.
   - Log: `"✅ Fastlane initialized successfully."`

### Step 1 — Parse User Request & Desired Flags

Inspect what the user requested. By default, the automated release performs the full end-to-end pipeline:
1. Version code increment in `app/build.gradle.kts` & Git commit
2. APK build via Gradle
3. Google Drive upload
4. Firebase App Distribution
5. Slack announcement with APK filename link and "What's new" bullet points

Map any user customizations to the appropriate Fastlane options:
| User Request | Fastlane Flag |
|---|---|
| Skip "What's new" / changelog | `skip_whats_new:"true"` |
| Skip Firebase App Distribution | `skip_firebase:"true"` |
| Skip Google Drive upload | `skip_gdrive:"true"` |
| Skip Slack notification | `skip_slack:"true"` |
| Skip version bump / keep version | `skip_bump:"true"` |
| Specify custom version name | `version_name:"X.Y"` |
| Custom changelog bullet points | `whats_new:"• Custom change 1\n• Custom change 2"` |
| Clean build | `clean:"true"` |

---

### Step 2 — Run the Unified Fastlane Release (Single Command)

Execute the single unified `release` lane from the project root:

```bash
bundle exec fastlane release flavor:"[Flavor]" [FLAGS...]
```

**Examples:**
- Standard full release:
  ```bash
  bundle exec fastlane release flavor:"oparkQa"
  ```
- Release skipping "What's new":
  ```bash
  bundle exec fastlane release flavor:"oparkQa" skip_whats_new:"true"
  ```
- Release skipping Firebase:
  ```bash
  bundle exec fastlane release flavor:"oparkQa" skip_firebase:"true"
  ```
- Release skipping both Firebase and "What's new":
  ```bash
  bundle exec fastlane release flavor:"oparkQa" skip_firebase:"true" skip_whats_new:"true"
  ```

> **Why this single command is critical:**
> Running the entire release inside Fastlane guarantees:
> - **Only 1 permission prompt** per deployment (or **0 prompts** if the user clicks "Always Allow").
> - Fastlane handles Gradle, Git, Google Drive, Firebase, and Slack natively in a single process without stopping for ad-hoc terminal approvals.

---

### Step 3 — Extract and Report Release Summary to User

Fastlane logs the completed steps and URLs. Once Fastlane finishes, extract the details from the log:
- **Flavor & Version**: e.g. `oparkQa`, `2.72 (791)`
- **APK Filename**: e.g. `oparkQaRelease-2.72-791.apk`
- **Google Drive Link**: Shareable link to the APK
- **Firebase App Distribution Link**: Tester URL (if enabled)
- **Slack Notification**: Delivered to `#parkiwi` from user profile

Present the final formatted summary table and changelog to the user.

## Error Handling Rules

| Situation | Action |
|---|---|
| Google Drive MCP fails to list files | Use the versionCode from `build.gradle.kts` as baseline and warn the user |
| Fastlane exits with non-zero code | Stop immediately, do NOT notify Slack. Report the error log to the user. |
| Git working tree is dirty (uncommitted changes detected before build) | **Auto-commit all uncommitted tracked files** with a descriptive message. Inspect the changed files to infer context (e.g. UI changes → `"feat: update [screen name] UI"`), then run `git add -u && git commit -m "[inferred message]"`. Report what was committed to the user before proceeding. Untracked files (`??`) are ignored — do not add them. |
| Slack MCP unavailable or fails | Fall back to Slack Web API (`chat.postMessage`). If both fail, report failure to user and provide the release message as plain text so they can post manually |
| Drive link not found in logs | Use the folder URL as the fallback link and warn the user |

## Important Constraints

- ❌ **Never modify** an existing `fastlane/Fastfile` or configuration (only initialize it in Step 0 if completely absent).
- ❌ **Never modify** any flavor block other than the one requested.
- ❌ **Never push** to git (no `git push`). Only commit locally.
- ✅ Always confirm the flavor-to-Drive-folder mapping before uploading.
- ✅ Always show the user a summary of what changed (version bump, APK name, Drive link) before posting to Slack.
- ✅ Use the project root for all commands.
