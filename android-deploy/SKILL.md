## Execution Steps (Run in Strict Order)

### Step 0 — Pre-flight Check: Initialize Fastlane if Missing

Before building, verify if Fastlane is already set up in the project:
1. Check if `fastlane/Fastfile` exists.
2. **If `fastlane/Fastfile` already exists:** Skip this step and do NOT modify it.
3. **If `fastlane/Fastfile` is missing (e.g. New Project):**
   - Notify the user: `"⚡ Fastlane setup missing. Initializing Fastlane configuration for Android..."`
   - Create or update `Gemfile` in the project root:
     ```ruby
     source "https://rubygems.org"
     gem "fastlane"
     gem "fastlane-plugin-google_drive_uploader"
     ```
   - Create `fastlane/Pluginfile`:
     ```ruby
     # Autogenerated by fastlane
     gem 'fastlane-plugin-google_drive_uploader'
     ```
   - Create `fastlane/Fastfile` with the standardized template:
     ```ruby
     default_platform(:android)

     platform :android do
       desc "Build APK and upload to Google Drive"
       lane :build_apk do |options|
         flavor = options[:flavor]
         build_type = options[:build_type] || "Release"
         should_upload_to_gdrive = options[:upload_to_gdrive].to_s == 'true'

         task_variant = (flavor && !flavor.strip.empty?) ? "#{flavor}#{build_type.capitalize}" : build_type.capitalize
         gradle_task = "assemble#{task_variant}"

         UI.message("Executing Gradle task: #{gradle_task}")
         gradle(task: gradle_task)

         apk_path = lane_context[SharedValues::GRADLE_APK_OUTPUT_PATH]

         if apk_path && File.exist?(apk_path)
           UI.success("APK successfully built: #{apk_path}")

           if should_upload_to_gdrive
             drive_folder_id = options[:drive_folder_id] || ENV["GDRIVE_FOLDER_ID"]
             if drive_folder_id
               google_drive_uploader(
                 client_secrets_path: "./fastlane/client_secrets.json",
                 token_store_path: "./fastlane/gdrive_token.yaml",
                 file_path: apk_path,
                 folder_id: drive_folder_id,
                 make_public: true
               )
             else
               UI.important("Google Drive Folder ID not provided. Skipping upload.")
             end
           end
         end
       end
     end
     ```
   - Ensure `fastlane/client_secrets.json` and `fastlane/*.yaml` are added to `.gitignore`.
   - Run `bundle install` in the background.
   - Log: `"✅ Fastlane initialized successfully."`

### Step 1 — Determine the Current Highest versionCode from Google Drive

Use the **Google Drive MCP** to list all files inside the folder that corresponds to the requested `[Flavor]`:

```
gdrive.list_files(folder_id: "<FOLDER_ID_FOR_FLAVOR>")
```

- Scan all filenames. APK filenames follow the pattern:
  `[FlavorVariant]-[versionName]-[versionCode].apk`
  (e.g. `oparkQaRelease-2.72-788.apk`)
- Extract the highest `versionCode` found.
- Compare against the value currently in `app/build.gradle.kts` for that flavor's product block.
- **Use whichever value is greater** as the baseline before incrementing.
- Log: `"✅ Drive highest versionCode for [Flavor]: [X]"`

---

### Step 2 — Bump versionCode in `app/build.gradle.kts`

1. Open [`app/build.gradle.kts`](file:///Users/tapangohil/StudioProjects/payg-android/app/build.gradle.kts).
2. Locate the correct `productFlavors` block for the **product** part of the flavor:
   - `opark` block for any `opark*` flavor
   - `vpark` block for any `vpark*` / `vPark*` flavor
   - `defaultConfig` block for `parkiwi*` and `paybyapp*` flavors
3. **Increment `versionCode` only** by 1 from the baseline determined in Step 1.
4. **⛔ Do NOT auto-change `versionName`.** Instead, ask the user:
   > "Current `versionName` is `[currentVersionName]`. Do you want to update it? If yes, please provide the new value."
   - Wait for the user's response.
   - If the user provides a new `versionName`, apply it. Otherwise, leave it unchanged.
5. Write the changes back to `app/build.gradle.kts`.
6. **Do NOT touch any other field or any other flavor block.**

---

### Step 3 — Commit the Version Bump to Git

Run these git commands in the project root:

```bash
git add app/build.gradle.kts
git commit -m "chore: bump [Flavor] versionCode to [newVersionCode] [skip ci]"
```

Replace `[Flavor]` and `[newVersionCode]` with the actual values.
If `versionName` was also updated, use:
```bash
git commit -m "chore: bump [Flavor] version to [newVersionName] ([newVersionCode]) [skip ci]"
```

Log: `"✅ Git commit done."`

---

### Step 4 — Run the Fastlane Build and Upload

Execute the Fastlane lane in a terminal from the project root:

```bash
bundle exec fastlane build_apk flavor:"[Flavor]" build_type:"Release" upload_to_gdrive:"true"
```

- **Do not modify the Fastfile.**
- Wait for Fastlane to finish completely before proceeding.
- Monitor the terminal output; Fastlane prints success/error lines like:
  ```
  ✅ Found renamed APK: /path/to/oparkQaRelease-2.73-789.apk
  ✅ Successfully uploaded oparkQaRelease-2.73-789.apk to Google Drive.
  ```

---

### Step 5 — Extract Upload Details from Logs

After Fastlane completes, read the terminal output and extract:

1. **APK filename** — from the line matching: `Found renamed APK:` or `Successfully uploaded ... to Google Drive`
2. **Google Drive shareable link** — Fastlane's `google_drive_uploader` plugin prints a shareable link after upload. Look for lines matching:
   - `"https://drive.google.com/file/d/..."` or
   - `"Shareable link:"` or similar
   - If Fastlane does not print a direct link, construct it using the Drive folder ID for the flavor:
     `https://drive.google.com/drive/folders/<FOLDER_ID_FOR_FLAVOR>`

Log: `"✅ APK: [apk_filename], Drive link: [drive_link]"`

---

### Step 6 — Summarize Recent Git Commits

Run:

```bash
git log --oneline -10
```

1. **Filter out all version bump / chore commits** (e.g. commits starting with `chore: bump`, mentioning `versionCode`, or tagged `[skip ci]`). **Do NOT include version change messages in the changelog summary.**
2. From the remaining commits, take the 3 most recent meaningful code / feature / bugfix commits.
3. Produce a concise, plain-English summary (bullet points preferred) of recent changes. Example:
   - • Updated payment card UI and layout resources
   - • Fixed issue in WelcomeFragment when Firebase initialization fails
   - • Updated location icon styling on the Home screen

---

### Step 7 — Post Release Notification to Slack

Check if the **Slack MCP** is available in the current environment:
- **If Slack MCP is available:**
  Use `slack.post_message` with `channel: "#parkiwi"`, `text: "🚀 New [Flavor] build released: [newVersionName] ([newVersionCode])"`, and the rich `blocks` structure below.
- **If Slack MCP is NOT available or fails:**
  Fall back to the Slack Web API (`https://slack.com/api/chat.postMessage`) using the bot token defined in `~/.gemini/config/mcp_config.json` (or `~/.gemini/antigravity-cli/mcp_config.json`).
  Send a POST request with headers `Authorization: Bearer <SLACK_BOT_TOKEN>` and `Content-Type: application/json; charset=utf-8`.
- If both MCP and API fail, display the full formatted release note in the chat so the user can post it manually.

- On success, log: `"✅ Slack notification sent to #parkiwi"`

## Error Handling Rules

| Situation | Action |
|---|---|
| Google Drive MCP fails to list files | Use the versionCode from `build.gradle.kts` as baseline and warn the user |
| Fastlane exits with non-zero code | Stop immediately, do NOT notify Slack. Report the error log to the user. |
| Git working tree is dirty (uncommitted changes detected before build) | **Auto-commit all uncommitted tracked files** with a descriptive message. Inspect the changed files to infer context (e.g. UI changes → `"feat: update [screen name] UI"`), then run `git add -u && git commit -m "[inferred message]"`. Report what was committed to the user before proceeding. Untracked files (`??`) are ignored — do not add them. |
| Slack MCP unavailable or fails | Fall back to Slack Web API (`chat.postMessage`). If both fail, report failure to user and provide the release message as plain text so they can post manually |
| Drive link not found in logs | Use the folder URL as the fallback link and warn the user |
